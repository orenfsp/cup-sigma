# «Отклик» — Платформа доверительных обращений

**MVP платформы анонимных обращений с бережным интерфейсом, умной маршрутизацией к профильным специалистам и автоматической детекцией кризисных ситуаций.**

Разработано для образовательной среды (школьники, родители, педагоги) в рамках хакатона «Кубок Федерации».

---

## 1. Инструкция по запуску

Проект полностью Open Source и может быть запущен двумя способами: через Docker Compose (одной командой) либо локально для разработки.

### Вариант А. Запуск одной командой через Docker Compose (Рекомендуемый)

Убедитесь, что у вас установлены Docker и Docker Compose. Из корня проекта выполните:

```bash
docker compose up --build
```

После старта сервисов:
- **Веб-интерфейс платформы**: [http://localhost:3000](http://localhost:3000)
- **REST API бэкенда (Swagger Docs)**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **База данных PostgreSQL**: `localhost:5432`

---

### Вариант Б. Локальный запуск без Docker

#### 1. Бэкенд (FastAPI, Python 3.11)
```bash
cd backend
python -m venv venv
# Windows:
.\venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
python main.py
# Бэкенд запустится на http://127.0.0.1:8000 (по умолчанию SQLite otklik.db, seed-данные применяются автоматически)
```

#### 2. Фронтенд (Next.js 16, React 19, Tailwind CSS)
```bash
cd frontend
npm install
npm run dev
# Фронтенд запустится на http://localhost:3000
```

## 3. Описание модели приватности и безопасности

1. **Нулевой сбор идентифицирующих данных (Zero-Knowledge Identity):**
   - У заявителя **не запрашиваются** имя, фамилия, школа, класс, телефон или email.
   - Единственным ключом доступа к обращению и переписке является случайный криптографический трек-номер.
2. **Изоляция технических метаданных:**
   - IP-адрес и User-Agent **не сохраняются** в базу данных и не связываются с обращением.
   - Полностью отсутствуют сторонние трекеры (Яндекс.Метрика, Google Analytics, пиксели соцсетей).
   - Сессии браузера не связывают между собой несколько обращений одного человека.
3. **Очистка вложений (Anti-Metadata Sanitization):**
   - Все загружаемые скриншоты переписок и фото проходят обязательную серверную очистку: EXIF-теги, геолокация и информация об устройстве удаляются перед сохранением на диск.
4. **Строгая матрица доступа (Role-Based Data Isolation):**
   - **Оператор** видит только исходный текст обращения и ответы на уточняющие вопросы. После назначения обращение ведёт эксперт; оператор **не имеет доступа** к дальнейшей закрытой переписке.
   - **Эксперт** не знает личности заявителя ни на одном этапе. Общение идёт от «Единого голоса сервиса» («Специалист», «Психолог») без раскрытия персональных данных.
   - **Администратор** не видит текстов обращений и не участвует в переписке. Вмешательство в зависшие заявки обязательно фиксируется в Журнале аудита.
   - **Аналитика и экспорт** содержат строго обезличенные числовые метаданные (ID, хэш трека, категория, статус, тайминги). Тексты обращений и переписок исключены из выгрузок на уровне SQL-запроса.

## 4. Принятые решения по трек-номеру и уведомлениям

### Трек-номер
- **Формат**: `ОТК-XXXX-XXXX` (например, `ОТК-K7N4-92WX`).
- **Алфавит**: 31 криптографически стойкий символ (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`), полностью исключающий визуально схожие символы (`0` и `O`, `1` и `I` и `l`).
- **Стойкость**: генерируется с использованием криптографического генератора случайных чисел `secrets` (энтропия исключает подбор).
- **Защита от перебора (Rate Limiting)**: ограничение до 5 запросов проверки трек-номера в минуту с одного адреса. При превышении возвращается HTTP 429 с расчётом времени ожидания.
- **Механизмы защиты от потери номера**:
  1. Кнопка «Скопировать номер» с визуальной индикацией.
  2. Кнопка «Скачать памятку» (текстовый файл с номером и датой обращения).
  3. Опция локального сохранения на устройстве пользователя (`localStorage` с согласия).

### Уведомления анонимного заявителя
- Поскольку у анонимного пользователя нет привязки к почте и телефону, основным сценарием является возврат по сохранённой ссылке/закладке либо по трек-номеру.
- В системе реализована поддержка PWA Web Push уведомлений без привязки к личности пользователя (анонимный push-токен устройства).
- При кризисных ситуациях заявителю предоставляется добровольная возможность оставить экстренный контакт (Telegram или телефон) с чётким предупреждением о том, кто и в каких случаях получит к нему доступ.

## 5. Решение открытой задачи ТЗ: Реагирование при кризисах и работа с органами

В случаях, когда заявитель сообщает об угрозах жизни, тяжком насилии или преступлениях против несовершеннолетних:
1. **Двухуровневый шлюз экстренной помощи**:
   - Система моментально выводит ненавязчивый баннер федеральных экстренных служб (Единый детский телефон доверия 8-800-2000-122, 112) прямо во время набора текста, не прерывая рассказ.
   - Заявителю предлагается опциональное поле экстренной связи, которое шифруется и доступно **только оператору кризисной линии**.
2. **Протокол «Доверительный мост» (Liaison Referral Code)**:
   - Если заявитель категорически отказывается передавать свои контакты, система генерирует для него защищённый разовый «Код происшествия» (Incidence Token).
   - Заявитель может назвать этот код специалисту Горячей линии или инспектору по делам несовершеннолетних, что позволяет профильным службам запросить у оператора платформы контекст инцидента через защищённый протокол без деанонимизации истории заявителя на самой платформе.

## 6. Прохождение приёмочных сценариев (С1 — С8)

- **С1. Подача свободным текстом**: выбор «Школьник» -> переключение интерфейса на «ты» -> свободное описание -> уточняющие вопросы -> очистка вложений -> получение трек-номера `ОТК-XXXX-XXXX`.
- **С2. Подача по категории от взрослого**: выбор «Родитель»/«Педагог» -> переключение интерфейса на «вы» -> выбор категории -> наличие обязательного пункта «Не знаю, как назвать» -> попадание в очередь оператора.
- **С3. Работа оператора**: вход оператором -> очередь новых с подсказками системы по категориям -> назначение приоритета и исполнителя (статус «Распределено») -> отклонение второго обращения как спам с указанием причины -> вкладка контроля «зависших» обращений без доступа к приватной переписке.
- **С4. Работа эксперта**: вход экспертом -> только назначенные обращения (срочные сверху) -> взятие «В работе» -> уточняющий вопрос («Нужно уточнение») -> закрытые внутренние заметки -> подключение соисполнителя / запрос передачи -> отправка рекомендаций («Ответ готов»).
- **С5. Возврат заявителя и ветка «не помогло»**: вход по трек-номеру -> ответ на вопрос эксперта -> получение рекомендаций -> кнопка «Это не помогло» с указанием причины -> возврат в очередь оператора (не эксперта) -> переназначение -> кнопка «Это помогло» и оценка 1–5 звёзд -> проверка ограничения частоты запросов при неверном трек-номере.
- **С6. Кризисное обращение**: ввод текста с маркерами угроз/насилия -> мгновенный показ контактов помощи без блокировки ввода -> опциональный экстренный контакт -> статус «Срочно» и верхняя позиция с таймером в очереди оператора.
- **С7. Администрирование**: добавление категории -> настройка правила «категория — группа — лимит» -> создание сотрудника -> разблокировка зависшей заявки с фиксацией причины в Журнале аудита.
- **С8. Аналитика**: дашборд с метриками (объёмы, распределения, время триажа, первого ответа, закрытия, возвраты) -> выгрузка CSV без текстов обращений.

## 7. Список нереализованного (Roadmap на будущее)

1. **Нейросетевой классификатор на базе легковесной локальной LLM/BERT**:
   - В текущей версии для надёжности и мгновенного старта используется стемминг и словарь кризисных маркеров. На следующем этапе планируется интеграция квантованной модели (например, ruBERT-tiny2) для детекции скрытых паттернов психологического давления.
2. **Анонимные сквозные аудио-звонки (WebRTC)**:
   - Возможность безопасного голосового звонка психологу прямо из браузера без раскрытия номера телефона и с опциональной модуляцией голоса.
3. **PWA Offline-First кэширование**:
   - Сохранение черновика обращения в защищённом хранилище IndexedDB на случай внезапного обрыва интернет-соединения в стрессовой ситуации.
